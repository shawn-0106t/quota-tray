Segmented control — the selected state has two different jobs

Both controls are the same component (.seg), same geometry, same neutrals. The difference is only how the selected cell announces itself. WCAG 1.4.11 asks for 3:1 between a state indicator and its surroundings; a fill difference of 1.14 (light) / 1.33 (dark) is not one. The desaturated columns are the honest test — remove the hue and ask what is still there.

Resolved 2026-11-14: the ring moved onto --seg-ring, so both the panel tab and the settings window are ringed with the accent and there is no second way to say "selected". This page is kept as the record of why.

The cost of not fixing it: a low-vision or bright-screen user sees three cells of nearly equal weight. The selected one is one weight step heavier and nothing else — measured 1.16 / 1.82 on the ring, against 3:1 required.

What it cost: one more role for the accent. It now means usage (bars, chip) and "this cell is selected" (the ring), declared in PLAN §3.5. The change was one value in --seg-ring, which both controls already read.

Numbers are produced by python demo/check_contrast.py (the E rows); the neutrals here are the real --seg-track / --seg-on / --seg-ring values.
